# نصب یک‌مرحله‌ای سرور تازه در ربات Madar

## رفتار پیش‌فرض برای نصب‌های جدید

در حالت فروش (`app_mode=reseller`) وقتی مدیر سرور **تازه** را از طریق ربات ثبت و نصب می‌کند، Runner از همان دسترسی موقت و تأییدشدهٔ SSH استفاده می‌کند و این کارها را بدون دستور جداگانه انجام می‌دهد:

1. تأیید مالکیت سرور و آزاد بودن پورت عمومی 443، دو پورت جایگزین 2053 و 8443 و پورت‌های داخلی سهمیه.
2. آماده‌سازی و نصب Xray و Agent با REALITY اصلی TCP 443 و کد مسیرهای جایگزین مستقل. هیچ پورت داخلی 20000–20999 در مسیر عمومی تبلیغ نمی‌شود.
3. روی نمونهٔ AWS که دقیقاً با IP سرور جدید منطبق باشد، Runner از نقش موقت IAM خود برای بازکردن TCP 2053 و 8443 علاوه بر 443 استفاده می‌کند؛ هیچ تغییری در AWS Node1 یا گروه امنیتی یک IP دیگر انجام نمی‌شود.
4. پس از پاسخ موفق نصب، Runner به Worker گزارش می‌دهد `freshInstall:true,protocolVersion:2,autoRealityPorts:[2053,8443]`.
5. Worker فقط برای نصب جدید و بدون سابقهٔ آماده، پروفایل‌های جایگزین را در D1 فعال و منشأ را `auto_installed=1` ثبت می‌کند. تنظیمات غیرفعال‌شده توسط مدیر بازنویسی نمی‌شوند.
6. Agent سیاست امضاشده را دریافت می‌کند و یک Xray جانبی برای پورت‌های 2053 و 8443 ایجاد می‌کند؛ تمام اتصال‌ها به همان backend حجمی حساب مربوط می‌شوند. اگر پورت اشغال باشد یا API ثبت کاربر شکست بخورد، مسیر اصلی 443 مستقل می‌ماند.
7. پس از ACK معتبر و تازه `reality-alt-metered`، لینک اشتراک به‌روزشوندهٔ همان مشتری سه کانفیگ ارائه می‌دهد: REALITY 443، REALITY 2053 و REALITY 8443. یک UUID، یک حجم، یک مدت و یک سیاست ابطال دارند.

## مرز این قابلیت

- سرورهای فعال و نصب‌های مجدد به‌صورت خودکار به چندپورتی مهاجرت نمی‌کنند.
- این تغییرات جایگزین به‌روزرسانی یک‌بارهٔ **Runner نصب سرور** نیستند؛ Runner باید نسخهٔ شامل این اصلاحات را اجرا کند تا گزارش جدید ارسال شود. اجرای Worker به‌تنهایی برای یک Runner قدیمی کافی نیست.
- «پورت نصب شد» به معنی تضمین دسترسی از ایرانسل یا همراه اول نیست؛ فقط ACK زندهٔ خود Xray مانع صدور کانفیگ غیرواقعی می‌شود.
- در ارائه‌دهنده‌های غیـر AWS که فایروال ابری جدا دارند، بدون اتصال مدیریت آن ارائه‌دهنده نمی‌توان باز شدن پورت خارجی را قطعی دانست. ربات حق ندارد قابلیت Reachability تأییدنشده را به مشتری تضمین کند.
- VMess/WSS فقط با یک ورودی HTTPS پایدار و مجاز به اشتراک اضافه می‌شود؛ دامنه یا ورودی WSS بدون وجود واقعی آن ساخته یا ادعا نمی‌شود.
- سرویس اصلی مشتریان فعلی و AWS Node1 هیچ تغییری دریافت نمی‌کنند. جهت نصب جانبی سرور قدیمی، مسیر ایزولهٔ `secondary-sidecar-live-install.md` جدا باقی می‌ماند.

## معیار پذیرش

برای یک نود تازه پس از نصب، باید رکوردهای `managed_reality_alt:<nodeId>:enabled=1`، `ports=[2053,8443]` و `auto_installed=1` ساخته شوند، سپس Policy با همین فهرست امضا شود. تنها زمانی که Agent روی همان revision، `reality-alt-metered` را همراه با سلامت Xray گزارش کرد کانفیگ اضافی صادر شود. همهٔ این مراحل باید بدون فشردن دکمهٔ تنظیم پورت یا اجرای SSH دوم انجام شوند.
