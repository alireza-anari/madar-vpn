# نصب ایمن مسیرهای جایگزین مدار روی آریانت (بدون توقف ۴۴۳)

این راهکار برای نود مدیریت‌شده Madar با `protocolVersion=2`، REALITY مشترک روی 443، و Xray نصب‌شده در `/opt/madar-sales-node` طراحی شده است.

**وضعیت:** قابلیت Worker و دکمه پنل مدیر می‌توانند منتشر شوند، اما تا زمانی که دستور زیر مستقیماً از SSH **همان VPS** اجرا نشود، پورت‌های جدید به مشتری داده نمی‌شوند.

## نصب یک‌مرحله‌ای با مرجع تغییرناپذیر

در SSH سرور آریانت (نه روی سیستم محلی) دستور زیر را به عنوان root/sudo اجرا کن:

```bash
curl -fsSL https://raw.githubusercontent.com/alireza-anari/madar-vpn/921c858f72d0f9bb1d1122be6a4c91f759244a1b/sales-node/install_secondary.py -o /tmp/madar-secondary-install.py &&
echo 'b0b0265804cce2b854ab33f3e016d8e1027220d4772df3bb87fa66793b86787e  /tmp/madar-secondary-install.py' | sha256sum -c - &&
sudo python3 /tmp/madar-secondary-install.py --node-id c6683027-498d-40ef-ae97-e5a725f0a86f --source-ref 921c858f72d0f9bb1d1122be6a4c91f759244a1b --manifest-sha256 4809f041c8f41d031f4d301889d8e4092a4792cb5b95ef2b98f0b9bba51fe94c
```

این دستور هیچ توکن، کلید خصوصی، رمز SSH یا متغیر Cloudflare را جابه‌جا نمی‌کند. نصب‌کننده، هش فایل‌ها، مالکیت واقعی Xray 443 و آزادبودن پورت‌های 2053 و 8443 را پیش از ساخت سرویس بررسی می‌کند. از `source-manifest` جداگانه استفاده می‌شود؛ نصب‌کنندهٔ قدیمی `update_owned.py` که Agent و Xray اصلی را متوقف می‌کند **نباید** برای این مرحله استفاده شود.

## فعال‌سازی در ربات

در پنل مدیر: «سرورها ← آریانت ← 🔀 پروتکل‌ها و پورت‌ها». پورت 2053، 8443 یا هر دو را انتخاب و تأیید کن. سپس یک حساب آزمایشی صدور کن و دکمه «🔄 لینک اشتراک به‌روزشونده» را باز کن. سرویس جانبی، سیاست امضاشده و دسترسی به همان backend حجمی را بررسی می‌کند و سلامت خود را از API احرازشدهٔ `/api/node/secondary-ack` گزارش می‌دهد. با تأیید کمتر از ۲۰ ثانیهٔ قبل، کانفیگ‌های پورت‌های جایگزین در لینک اشتراک ظاهر می‌شوند.

پورت 443 از این نصب مستقل باقی می‌ماند و همیشه در جای اول لینک اشتراک است. هر سه کانفیگ یک UUID و یک سهمیه حجم/انقضا دارند. **این قابلیت پایداری یا سرعت ایرانسل را تضمین نمی‌کند.**

ممکن است فایروال سیستم‌عامل یا پنل VPS، اتصال خارجی TCP به 2053 یا 8443 را مسدود کرده باشد. بازکردن پورت باید فقط برای پورت مورد نیاز انجام شود؛ این نصب‌کننده به‌صورت خودکار فایروال، DNS یا مسیر WSS را تغییر نمی‌دهد.

## بررسی و بازگشت

```bash
sudo systemctl is-active madar-sales-node.service madar-sales-xray.service madar-sales-secondary.service
sudo ss -ltnp | grep -E ':(443|2053|8443)[[:space:]]'
sudo journalctl -u madar-sales-secondary.service --no-pager -n 30
```

برای برگشت فوری پورت‌های جانبی (بدون توقف سرویس اصلی):

```bash
sudo systemctl disable --now madar-sales-secondary.service
```

سپس در ربات پورت‌های جانبی را غیرفعال کن. نبود heartbeat معتبر، باعث می‌شود کانفیگ‌های جانبی پس از حداکثر ۲۰ ثانیه از لینک اشتراک حذف شوند.

## مرزهای ایمنی

- هیچ تغییر یا restart روی `madar-sales-node.service` یا `madar-sales-xray.service` اعمال نمی‌شود.
- Xray جانبی فقط به loopback backendهای حجمی موجود خروجی دارد و مسیر پیش‌فرض آن blackhole است.
- خرابی API حذف دسترسی، باعث توقف همان Xray جانبی می‌شود، نه سرویس اصلی.
- API رابط جانبی فقط با توکن موجود همان نود و سیاست امضاشده/تأییدشده، heartbeat می‌پذیرد.
- تست میدانی روی ایرانسل و تأیید وضعیت فایروال بعد از نصب همچنان ضروری است.
- مسیر VMess/WSS بدون ورودی HTTPS پایدار همچنان غیرفعال است.
