# One-time Node1 Runner bootstrap

The owner approved preparation of a background installer for Node1 after direct SSH from the cloud workspace failed with Network is unreachable. The owner reported removing the temporary SSH key. No SSH/firewall modification is part of bootstrap.

Run the exact pinned bootstrap.sh through systemd-run once from EC2 Instance Connect as ubuntu. The command verifies the shell script SHA256 before root execution. It downloads a hash-checked manifest of public source files at that same immutable commit, creates a dedicated system account and venv, and generates the Runner RSA private key on Node1 only. It does not install a VPN node on Node1 or alter existing Madar/Xray services. Python venv support may be installed through apt if absent.

The temporary ops-entry.ts Worker entrypoint preserves canonical bot behavior and adds only POST /ops/runner-bootstrap/pair. This route expires at its compiled deadline, checks Cloudflare's source IP for the approved Node1 address, bounds input, validates the public RSA key and SHA256 identity, and pins the first identity atomically in D1 settings. The identity is public. It returns no service secret before operator approval and only an RSA-OAEP/AES-GCM sealed envelope after approval. Cloudflare secret values are never returned in plaintext.

After the command runs, operator reads runner_bootstrap_candidate (public key/fingerprint only) and compares the fingerprint with Node1 journal output. The owner confirms the short fingerprint. Configure RUNNER_SERVICE_SECRET and POLICY_SIGNING_SECRET through the Cloudflare Secret API without printing values; configure RUNNER_PUBLIC_KEY to the approved JWK while preserving all other bindings. Encrypt {baseUrl,serviceSecret,runnerId,fingerprint} for that public key using RSA-OAEP SHA256 + AES-256-GCM and insert only the ciphertext in runner_bootstrap_envelope with its fingerprint. Never put plaintext service secrets or private keys in D1 evidence, chat, argv or git.

The root bootstrap polls for at most 30 minutes. It decrypts locally, writes mode-0600 runner.json tied to its local private key and exact Worker origin, transfers config ownership to the dedicated user, enables madar-sales-runner.service, and checks it active. The service runs unprivileged with restart after failures and reboot. A bootstrap restart reuses the same key; different existing config/unit is refused. Re-running prepare_identity preserves ownership and mode; keep /etc/madar-sales-runner private.

After actual service verification, restore the canonical Worker main_module index.js, deleting the temporary ops route, and delete the two bootstrap settings rows. Do not delete Runner config/key or the operational service. Then run real disposable-Ubuntu enrollment and customer acceptance. Existing VPN servers intentionally fail node-installer preflight and must not be reinstalled by inference.

Local tests are not a real Node1 installation witness. The owner must execute the prepared command; source-IP mismatch, unsupported Ubuntu, missing apt network or failed systemd remains a field blocker and must be reported without changing SSH/firewall.
